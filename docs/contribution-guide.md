# RocketMQ Studio 贡献说明

## 活动简介

**RocketMQ 5.0 Studio：全新的 AI-Native 管控平台**

RocketMQ 5.0 新增了云原生弹性架构、多语言 gRPC 接入、Lite Topic 等核心特性，完成了向 AI-Native 异步通信引擎的范式升级。本次社区共建活动旨在打造全新的 AI-Native 管控平台，由于任务较为复杂，拆分为三个方向：

- **赛道一：管控方向（AI-Native 统一管控平台）** — 打造 RocketMQ 5.0 Studio 核心可视化前后端服务，一站式实现多集群、多架构、多云环境的统一管控。
- **赛道二：协议升级（Proxy Admin 管控能力升级）** — 构建 Proxy Admin gRPC 协议标准，将客户端连接管理与运行时诊断能力全面标准化开放。
- **赛道三：AI Native（大模型原生集成）** — 借助 Skill + CLI 标准化能力封装，资源管理与运维操作可被 LLM 直接理解与调用。

## 参与方式

本次活动的形式以**开源贡献**为主，不同于天池、LeetCode、HackerRank 等以排名和积分为导向的竞赛平台：

- **按顺序合并**：贡献以 GitHub Issue 和 PR 为单位，按照提交顺序进行 Review 和合并，先到先得。没有额外的评分系统或排名机制，每一份有效贡献经过 Code Review 通过后即可合入代码库。
- **贡献记录**：所有被合并的 PR 将永久记录在 Apache 项目历史中，成为你开源履历的一部分。

## 赛道说明

### 赛道一：管控方向（AI-Native 统一管控平台）

项目已在 rocketmq-studio 上实现了一个前后端模板，技术栈选用 TypeScript + Java（Spring Boot 3.5 + Java 21），采用较为通用的后端管控平台架构，适合不同背景的开发者参与。
贡献者可直接提交 Issue 和 PR。建议每个改动控制在 **15 个文件以内**，以**功能模块为粒度**，支持前后端一起修改。每个 PR 应聚焦于单个功能模块的完整实现，确保可独立验证、独立回滚。

### 赛道二：协议升级（Proxy Admin 管控能力升级）

社区将提供由多位社区成员共同讨论制定的 gRPC admin proto 定义（不含具体实现），贡献者需基于该 proto 完成实现代码，代码需提交到 **RocketMQ 主仓库**（apache/rocketmq）的 **proxy 模块**下。
该赛道涉及底层架构设计与接口契约变更，**请先发起 Issue 讨论设计方案**，经过讨论后再提交 PR。

### 赛道三：AI Native（大模型原生集成）

本赛道将 RocketMQ 的资源管理与运维操作封装为标准化的 Skill，使 LLM 能够直接理解和调用这些能力。客户端 CLI 支持使用任意语言实现，但需提交设计方案评审；服务端 MCP 基于赛道一的 Java 后端，通过 remoting 协议管理对应的 Broker，所有复杂逻辑（鉴权、请求审计、LLM 调用）均在此集中处理。
该赛道涉及 Skill 规范与接口契约设计，**请先发起 Issue 讨论方案**，经过讨论后再提交 PR。
