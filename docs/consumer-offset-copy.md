# 按 Topic 复制消费位点

## 用途与前提

组迁移时，可以把一个普通 Topic 的源组位点复制到已有目标组。
入口位于 Apache 实例的消费组详情、消费进度表中的 `Copy topic offsets`。
每次操作覆盖该 Topic 的全部可读队列；即使从某一队列行进入，也不是单队列操作。
云实例和 Mock 模式不显示此入口。

操作前停止源组和目标组消费者，并保持停止状态直到核对结果完成。
两组必须已在每个 Topic 主 Broker 上配置；本功能不会创建消费组或停止客户端。
后端在预览和提交前分别检查两组连接，只接受空连接集合或明确的
`CONSUMER_NOT_ONLINE` 响应码；权限、超时等异常不能证明消费者离线。

## 操作步骤

1. 从源组消费进度进入复制窗口，填写已有目标组名称。
2. 点击 `Preview offsets`，核对全部 Broker、队列、目标原位点与源位点。
3. 确认源位点仍在保留范围内，并评估目标消息重放或跳过的业务影响。
4. 勾选确认项，再点击 `Copy reviewed offsets`。
5. 保存逐队列回执，读取目标实际位点并核对后再恢复消费者。

队列范围展示为可提交的游标范围 `[minOffset, maxOffset]`。
`maxOffset` 表示队尾下一条位置，允许把游标复制到这里；它不是已有消息的位置。
源位点缺失或超出范围会阻止整个提交。目标位点未保存时显示 `Not stored`，不视为零。
所有位点以十进制字符串传输，避免 JavaScript 对超过 `2^53 - 1` 的整数舍入。

## 两阶段检查与结果

预览使用 Topic 路由列举可读队列，再从集群登记信息选择 Broker ID 为 `0` 的主节点。
范围、源组位点和目标组位点都直接向该主节点读取。
提交前重新采样，对比全部队列身份、主节点地址、源位点和目标原位点。
这些内容变化时返回冲突，要求重新预览；保留范围变化后源位点失效也会阻止提交。
新消息追加导致队尾增长本身不会使位点预览失效。

提交逐队列调用 `updateConsumeOffset`，每次写入后读取目标位点确认。
第一次结果无法确认时停止后续队列，不自动重试，不自动回滚。

| 状态 | 含义 |
| --- | --- |
| `CONFIRMED` | Broker 确认写入，随后读取的目标位点等于请求值 |
| `UNCHANGED` | 提交前采样的目标位点已等于源位点，未发送写入 |
| `UNKNOWN` | 写入异常、回读失败或回读值不一致，实际副作用需要人工核实 |
| `NOT_ATTEMPTED` | 前一队列出现不确定结果，本队列未发送写入 |

每次尝试写入均记录源组、Topic、队列、原目标位点、请求位点和结果状态。
沿用操作审计服务；审计存储异常不会覆盖已经产生的操作回执。
POST 沿用管理员权限拦截；GET 仅执行预览读取。

## 并发、故障与恢复

多 Broker、多次请求之间没有分布式事务。离线检查之后，客户端仍可能重新连接，
其他管理员也可能修改位点。`CONFIRMED` 仅代表当次回读一致，不保证随后不再变化。
源组离线检查覆盖 Topic 涉及的主节点，不能代替操作人员停止整个消费应用。

浏览器切换实例、断网或关闭页面不能撤回已发出的 Broker 请求。
若 HTTP 响应丢失，应重新读取所有目标位点，不能假定全部失败并直接重试。
UI 消耗已提交预览；再次操作必须重新获取当前状态。

需要恢复时，保持目标消费者停止，按原预览中保存的目标位点逐队列核对和重置。
原来没有保存位点的队列无法通过本功能恢复为“未保存”；应按业务起始策略重新设置。
不要通过删除消费组来回滚本操作。

本功能不复制订阅配置、重试策略、重试消息、死信消息或其他 Topic。
无数据结构迁移，新增独立接口和入口；代码回滚可直接撤销该提交，已经写入的位点须按上述步骤处理。

## 实现依据与验证范围

参考 RocketMQ 5.5.0 的 [Admin 扩展接口](https://github.com/apache/rocketmq/blob/rocketmq-all-5.5.0/tools/src/main/java/org/apache/rocketmq/tools/admin/MQAdminExt.java)
和 [Admin 实现](https://github.com/apache/rocketmq/blob/rocketmq-all-5.5.0/tools/src/main/java/org/apache/rocketmq/tools/admin/DefaultMQAdminExtImpl.java)。
原生 `cloneGroupOffset` 按源组重试 Topic 选路，且 Broker 复制整个持久化队列表，
所以这里使用明确 Topic 路由和逐队列写入实现可审阅的迁移范围。

本地测试覆盖精度、两阶段冲突、主节点选择、离线响应码、部分成功、回读失败、
中断标记、审计异常及前端确认和请求生命周期。未连接真实 Broker 执行迁移，
未完成生产压力、容量和网络分区测试。最后验证日期：2026-09-08。
