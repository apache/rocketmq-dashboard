# 服务端共享命名查询

在 Message Explorer 的「服务端查询历史」抽屉中选择「已保存的消息查询」，可以在执行前保存当前 Topic、Key 或 Message ID 条件，随后搜索、应用、重命名或删除。应用只回填表单，点击「查询」才会执行；消息和轨迹执行历史仍保持原有行为。

命名查询按实例保存在 Studio 数据库，跨浏览器、跨操作者共享。复用既有认证策略：读者可以查看和应用，管理员可以修改。每实例最多 50 条，名称最多 80 个字符；同实例名称不区分大小写。达到容量上限会拒绝新增，不会自动淘汰已有查询。

数据使用 `rmq_named_message_query` 表，独立于执行历史，历史保留天数和清理任务不会删除命名查询。写入先锁定实例行，再使用当前锁定读检查容量，避免 MySQL 可重复读快照导致并发请求超出上限；数据库唯一约束防止重名。删除实例时对应命名查询级联删除。

## 接口

共同路径：`/api/query-history/named-messages`。

- `GET ?instanceId=...`：读取该实例共享查询。
- `POST`：保存名称和完整条件，不执行 RocketMQ 请求。
- `PUT /{id}?instanceId=...`：更新名称。
- `DELETE /{id}?instanceId=...`：删除命名查询。

无效参数返回 400；实例或查询不存在返回 404；名称重复或容量达到上限返回 409。刷新或保存失败均显示错误，不会将失败伪装成成功。

## 升级与回滚

启动时由 `QueryHistorySchemaMigration` 执行幂等脚本 `server/src/main/resources/db/named-message-queries.sql`，适用于已存在实例表的新旧数据库。常规应用重启即可完成建表，无需停写历史记录。建议在正常发布窗口执行并预先备份数据库。

未合入版本中的浏览器 localStorage 预设不自动上传为团队共享数据，以免将个人排查条件直接公开；需要保留的旧预设可在页面回填后重新命名保存。原本的执行历史无需迁移。

回滚应用提交即可移除新增入口与接口；保留新表不会影响旧版本，勿在回滚时删除已保存的共享数据。本文作为必要的中文设计注释；Java 源码遵循仓库禁止中文字符的 Checkstyle 规则，中文错误消息以 Unicode 转义保存。
